# 节点变更、配置发布与审计增强

2026-10-12：用户要求实现功能 1、2、6，实施验证后明确授权部署。
保留已有 node-forwarding.schema.ts 和 test-opaque-json-camel-case.ts 改动。

## 1. 节点编辑与用户变更

- 前端仅发送实际变动字段，服务端再次按实际字段比较，名称/地址 trim 后拒绝空白。
- 名称、供应商、标签、账单与流量阈值不触发核心下发。
- 用户事件按节点去抖并从当前数据库重新生成授权集，不重放过时密码/增删事件。
- 持久化期望与已处理序号，节点串行；在途新事件保留并续跑，重启和队列丢失后可恢复。
- 复用现有 Agent 全配置预检、原子应用和 last-known-good，不声称全协议零重启。

## 2. 配置发布与回滚

- 保存不可变的节点配置 revision、操作者、来源、批次、确认、耗时和结果。
- 敏感快照使用独立用途派生的 AES-GCM 加密；API 只返回摘要及脱敏变更路径。
- 回滚只回退配置，重新注入当前授权用户，禁止恢复旧用户密码或过期/禁用用户。
- 单节点显式回滚/解除固定版本，节点锁、异步状态、失败保留上一健康版本。
- 批次先灰度，成功后继续其余节点，任一失败停止后续节点，不误标成功。
- 历史按节点数量与保留期限制；当前应用/固定/在途 revision 不清理。

## 6. 访问审计

- 全筛选区间汇总，不受分页或 Top 20 截断影响；保留“连接累计参考字节”语义。
- 目标排行支持总量、上传、下载，并在 SQL 中排序后取 Top 20。
- CSV 导出最多 5000 条，超限要求缩小筛选，防公式注入，独立操作留痕。
- 可设置临时开启到期自动关闭，与历史保存天数分开；未设置到期的现有策略不变。
- 到期立即拒绝入库，即使协调定时器尚未执行；历史按原保留期处理。

## 验证与发布

隔离 PostgreSQL 并发/重放/回滚与审计测试，模块/权限启动回归、类型/生产构建、
前端模拟 API 浏览器回归。不得对线上主动注入故障、开启审计或运行测速。
版本号同步更新；后续发布必须 GitHub Actions 镜像、版本标签加 digest、面板备份。

## 实施完成

- Backend 3.19.0，contract 3.19.0-anytls.0，Frontend 3.18.0；Agent 代码和版本未修改。
- 节点编辑弹窗新增“配置发布与回滚”，可看脱敏摘要、操作者、结果/hash、耗时、回滚和解除固定。
- Profile 编辑器新增“仅保存，稍后灰度”。只允许保留入站标签和协议类型的变更；先给所有启用核心节点建立已确认 revision，否则明确拒绝，不猜测线上配置。
- 仅保存会原子固定已有模板，用户变更和后台恢复不会提前发布候选配置。灰度批次固定本次模板，灰度成功后逐台继续；停止批次不打断已经在途的节点。
- 回滚/灰度失败后恢复前一固定模板；若没有可确认基线则阻止自动重试，需显式发布。APP_SECRET 必须备份；丢失原密钥的历史快照不可解密。
- 禁用节点只保留期望状态，不调用核心；重启恢复与启停共用节点锁。保持原有禁用标记、IP 封禁、断开连接和转发控制分支。
- 历史保留 90 天，单节点最多 100 个普通 revision、200 条普通发布记录；当前、固定、在途和待发布批次引用的模板受保护。界面展示最近 100 条记录。

- “仅保存”走独立 POST /api/config-profiles/stage；旧后端会拒绝请求，不会忽略新参数后立即广播。前端/后端分批升级时也保持失败关闭。
